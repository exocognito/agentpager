## Facts for the build

- **Pager keys are already X25519** [V]: `Curve25519.KeyAgreement.PrivateKey` in `packages/ios/AgentPager/Model/Keychain.swift`, stored `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` with no access group [V]. Existing pagers keep their keys and numbers; their Keychain items only need to move where the alert extension can read them. Whether iOS lets the app move an item's access group in place is [A]: check early, and never delete an item before its copy reads back.
- **Built since M2** [V]: the number is `ap1_` + base64url(pager id 16 bytes ‖ fingerprint 8 bytes); the service stores each pager's public key (`registry.ts`, table `pagers_v2`) and checks the fingerprint at create and connect (`worker.ts`). The command doesn't check the key itself yet.
- **Storage today** [V]: one Registry Durable Object for all pagers, and one Agent object per agent with plaintext tables `proposals`, `answers`, `acknowledgements` and `attachments` (`agent.ts`). Answers already carry a `requestId` and are stored once; asks have none. No client-version header exists; replies carry `X-AgentPager-Build`.
- **Alerts** today put the question in plain text (`push.ts`, `questionBody()`).
- **The iPhone app from before the switch** [V, `AppModel.swift` › `apply()`]: a refusal shows only its general can't-reach line, and only `UnknownPager` drops a pager with its keys. So the service must never answer `UnknownPager` for a pager that exists, whatever the client's version.
- **Apple signing: only Sam can do it.** The alert extension is a new target with its own bundle id, so the development profile changes. Never create, request or use an Apple signing identity, certificate or app id for Sam, and never run `xcodebuild -allowProvisioningUpdates`. When the target exists, the root pages Sam to build once in Xcode on pro with automatic signing. `pnpm phone:dev` for HomePhoneLite waits on it; nothing else does. Whether Simulator UI tests run the extension without that profile is [A].
- **The format** uses X25519, HKDF-SHA256 and AES-256-GCM, in CryptoKit and in the command's runtimes (Node for its tests, Bun for its binary), with no new library. Shared test vectors in `packages/contract`, which the Swift and TypeScript sides both pass, come before either side's feature code. The service never encrypts or decrypts.
- **Screens:** any change to the app's sources, its UI tests, brief fixtures, the wire contract or the front page needs `pnpm designs`, about 9 minutes on pro, or `pnpm check` fails [V]. Simulator runs go one at a time across agents, under `lockf -k ~/Projects/agentpager-worktrees/.simulator.lock`.
- **Tests** are named by the id they prove (METHOD › Tests), Swift as `test_B30_1_…`.

## The root's calls for the build

Choices agents make, given to the builders; each lives in code once built.
- The phone encrypts an answer to the agent key carried inside the card's encrypted part, never to a key the service hands it, so a service that swaps an agent's key must also forge the question.
- The agent chooses the decision id. It is the ask's request id, and it is bound into each part for that decision.
- The warning that no agent picked up an answer resends the decision's stored encrypted preview, and the extension words the warning. The agent makes the acknowledgement's preview.
- The Keychain is shared through `keychain-access-groups` under the team prefix; no App Group unless a builder finds it needed.
- No reply to the app from before the switch says `UnknownPager` for a pager that exists.
