It's been 9 hours since you last read the card contract. The short version:
  1. One question per card. 2. Write for someone who wasn't there. 3. Context: what's happening, what breaks if nobody decides, how likely. 4. Options are different ways to get the job done; never "revise" or "discuss". 5–8. Each option's story; a tradeoffs table on what your owner cares about; recommend one; next steps. 9. What this fixes from the v1 timeline, and what it doesn't

  1. Rules read once at connect: fixed for MCP agents (present every turn) and covered for CLI agents by the reprint on the binary's clock. The review step is where the rules get applied to a card, by a reader that has them in front of it.
  2. Rules that set limits but never defined a good card: fixed by the contract text and the review list, which says what good looks like in a form a reviewer can grade.
  3. Server never coached: replaced. The server can't read cards now; the agent's own subagent reviews instead, once, before send.
  4. Corrections didn't carry forward: they don't need to. Every correction from last night is now a point on the review list applied to every card. A new kind of correction gets added to the list, versioned with the binary; it is not carried by notes.
  5. The harness prompt pulling toward "approve this package?": not fixed, and can't be from our side. The list names it (point 2) and a reviewer will usually catch it; nothing can make the writer think of a second real option. If reviews miss it in practice, that one item can be backed by a mechanical check, decided with data.
  6. Thin briefs handed to a helper: partly. A helper now gets a concrete refusal to take back to its coordinator ("Context links to a document; put what's needed in the card"), which is better than a silent send. It still can't invent what it wasn't told.
